# 2026-10-20

## faceplate alignment (dfx v0.1.17)

- The `imgui.Dummy` at the end of `MasterUI.DrawControls` looks like a no-op and is load-bearing. ImGui tables carry the largest text baseline offset any cell ends with (`RowTextBaseline`) into every later cell of the row, so a cell ending on a framed widget (the mute button) pushes the later cells' first `Text` down by `FramePadding.y` (5px under Faceplate, so the device labels sat below Headphones/Controls). The dummy ends the cell at baseline zero. Any new control added below the mute button stays above that dummy.
- The cue mix table pushes horizontal `CellPadding` to 0 because the separators are drawn at sums of the declared column widths; with style padding every column drifted right of its line (16px per boundary under Faceplate, 8px under Classic, which the old 25/12 padding constants had been tuned by eye against). If the table ever gets padding back, the separator arithmetic in `cuemix_ui.go` has to move with it.
- The second separator now sits `paddingAfterSep` past the Controls column instead of `paddingBeforeSep`, mirroring the first, so the centered controls sit midway between lines. That moves the faders 13px further from the line than before; deliberate.
